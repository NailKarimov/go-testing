## 4. Test approach

- **Levels:** API (most checks), UI (key user paths only), following the test pyramid.
- **Test design techniques:** equivalence partitioning, boundary value analysis, decision tables, state transitions.
- **Test data:** generated by factories in `src/data`, isolated per test, cleaned up after the run.
- **Environments:** set via `.env` / CI variables (`config/env.ts`).

## 6. Entry and exit criteria

- **Entry:** SUT is reachable, test data can be created, the suite type-checks and lints cleanly.
- **Exit:** all smoke tests pass; no open critical or major defects without an agreed workaround;
  pass rate ≥ 95 % with known defects documented.
